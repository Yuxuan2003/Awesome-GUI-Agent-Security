#### A Dual-Process Perspective on Nudge Susceptibility in LLM-Based GUI Agents (Nudge Susceptibility) (2026-09)

GUI agents act inside interfaces designed to support but also deliberately steer human decisions. Behavioural bias in LLM text output is well documented, but far less is known about how such influence operates once a model perceives an interface and executes decisions — and whether built-in reasoning makes agents more robust to it. Drawing on Dual-Process Theory, a randomized online-shopping experiment with 3,600 agents and 21,600 simulations across six frontier models from three providers finds agents vulnerable to both automatic (Type 1) and reflective (Type 2) digital nudges. Crucially, reasoning configuration moderates the two in **opposing** directions: it reduces susceptibility to automatic default nudges while heightening susceptibility to reflective social-influence nudges. Extensive reasoning therefore does not confer robustness — it redirects the route through which choice architecture takes effect, and that redirection is systematically structured by model scale.

#### HazardAuditor: From Executable Threats to Safer Computer-Use Agents (HazardAuditor) (2026-09)

Identifies two gaps that keep guard models from covering computer-use agents: existing guards target static prompts and responses, ill-suited to agent execution; existing executable safety platforms emit evaluation verdicts rather than the normalized supervision a guard model needs to learn across heterogeneous frameworks. HazardAuditor closes both — its infrastructure runs Claude Code, Codex, Hermes, and OpenClaw in controlled environments and normalizes their interactions into a canonical event representation enabling cross-framework supervision. The authors further observe a structural mismatch: token-level post-training objectives let longer rationales dominate gradient updates in generative guards. Guard Policy Optimization (GuardPO) converts deterministic safety outcomes into sequence-level advantages and normalizes rationale versus verdict regions, making the safety decision the effective unit of optimization. Accuracy improves by up to 16.5 points over the strongest prior guard.

#### Monitoring Web Agents Without Internal Signals: Observable Trajectories and Key-Step Supervision (Key-Step Supervision) (2026-09)

Reliable monitoring becomes hard precisely where it is most needed in practice: behind closed APIs, where model-internal signals such as token logits are unavailable. This work studies prefix-level risk prediction from observable signals only — given an evolving prefix, estimate whether execution is still on track. Two representations are derived: Macro features summarize cross-step agent-environment behavior and feedback; Micro features measure consistency among intention, action, and anticipated state change via repeated black-box queries. The supervision design is the notable part: instead of inheriting the final outcome label, the authors label the first uncorrected critical error associated with eventual failure as a key-step boundary, which preserves valid early prefixes of failed trajectories as on track — avoiding the label noise that makes naive outcome-based monitors fire too late or too often.

#### FocusMem: Factorizing Content, Readout, and Trust in Latent GUI Memory (FocusMem) (2026-08)

Latent memory compresses multimodal GUI trajectories into a few continuous tokens, but existing methods map each trajectory to one fixed block trained mainly by next-action supervision. Three problems follow: detail is lost in compression, one block must serve every decision stage, and irrelevant retrieved trajectories can still mislead the agent. FocusMem factorizes these responsibilities — a role-aware content basis pushes episodic memory toward reusable experience and working memory toward current task progress; a state-conditioned readout produces a decision-specific view of the same stored evidence; and a lightweight trust gate can suppress memory when retrieval is unreliable. That last component is why this belongs on a security list: it treats retrieved memory as untrusted input requiring gating, which is the structural defense against memory-poisoning style manipulation.
