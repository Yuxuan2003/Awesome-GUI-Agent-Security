# Contributing

## The one-line workflow

**Edit `data/papers.yaml` only.** `README.md`, `README.zh-CN.md`, and everything under `docs/`
are generated by GitHub Actions — do not edit them by hand, your changes will be overwritten.

---

## Scope (hard rules)

### ✅ In scope

The paper's **primary research subject** is a GUI agent / computer-use agent / browser agent /
mobile agent, **and** its contribution is about security: attacks, defenses, jailbreaks,
injection, privacy, backdoors, or risk evaluation.

### ❌ Out of scope

| Type | Why | Where it belongs |
|---|---|---|
| General LLM / agent security | GUI agents are just one of several test environments; the contribution is not specific to the GUI/CUA form factor | `LLMSecurity/awesome-agent-skills-security` |
| Using agents *for* security | Penetration testing, vulnerability discovery, CTF, threat hunting | `kagnlp/Awesome-Agentic-Security` |
| Agent auditing & provenance | Provenance, audit trails, observability | `yzhao062/awesome-auditable-ai` |
| Pure capability work | Grounding accuracy, task success rate, inference efficiency | `OSU-NLP-Group/GUI-Agents-Paper-List` |
| Embodied / robotics safety | Physical-world interaction as the main focus | `x-zheng16/Awesome-Embodied-AI-Safety` |

**Why the boundary is drawn this strictly**: comparable lists routinely lose scope discipline.
One GUI-agent safety list collected 42 papers, of which 18 — the **largest single group** — fell
under "Misc (general domains)", pulling in general LLM guardrail models and multimodal safety
benchmarks. The result was a CUA security list whose biggest section wasn't about CUAs.

**Quick test**: replace "GUI agent" / "computer-use agent" in the title with "LLM". If the
contribution still stands, it probably doesn't belong here.

### Time range

**2025.01 onwards only.** The date is the **arXiv v1 submission month**, not a v2/v3 revision —
CI compares against arXiv and will reject mismatches.

## Entry format

Append to `papers:` in `data/papers.yaml`:

```yaml
  - id: "2608.06477"
    title: "StepJack: Benchmarking Computer-Use Agent Safety Against Multi-Step Indirect Prompt Injection"
    abbr: "StepJack"
    date: "2026-08"
    venue: "arXiv"
    section: "1.1"
    env: [desktop, cross]
    summary: >-
      Existing indirect prompt injection benchmarks rely on single-step injections... Multi-step
      injection raises attack success by up to 31.2 points over single-step.
    summary_zh: >-
      针对现有间接提示注入评测多为单步的问题，提出多步 IPI 基准 StepJack，构造 480 个测试
      用例……实验显示多步注入相比单步把攻击成功率最高抬升 31.2 个百分点。
    code: https://github.com/...    # optional
```

### Fields

| Field | Required | Notes |
|---|---|---|
| `id` | △ | arXiv ID, **no version suffix**. Use `url` instead for non-arXiv sources |
| `title` | ✅ | Full official title, **must match arXiv exactly** (CI verifies) |
| `abbr` | | Method / benchmark abbreviation |
| `date` | ✅ | `YYYY-MM`, arXiv **v1** month |
| `venue` | | Conference / journal, or `arXiv` |
| `section` | ✅ | Section ID, see `data/sections.yaml` |
| `env` | ✅ | `web` / `mobile` / `desktop` / `cross`, multiple allowed |
| `summary` | ✅ | **English**, 3–5 sentences (primary version) |
| `summary_zh` | ✅ | **Chinese**, 2–4 sentences (secondary version) |
| `code` | | Code repository URL |

△ = at least one of `id` / `url`

**Both summaries are mandatory.** English is the primary version; Chinese is a full-fidelity
secondary version, not a truncated translation.

### Writing summaries

Three beats: **motivation → mechanism → key numbers**.

- ✅ `Claude Code backed by Qwen3-Coder reaches a 73.63% attack success rate`
- ❌ `experiments demonstrate significant effectiveness`

Numbers must name the metric and the value. In the Chinese version, keep technical terms in
English (`prompt injection`, `grounding`, `accessibility tree`) and write the prose in Chinese.

### Classification rules

- **One paper, one section.** For cross-cutting work pick the closest primary contribution and
  explain the call in the PR description.
- Classify by **attack vector**, not runtime environment — environment goes in the `env` field.
  Example: accessibility-tree injection on mobile → `1.3 Environmental Injection` with
  `env: [mobile]`, *not* into some "Mobile" chapter.
- Papers driven by an attack but whose main contribution is a **defense mechanism** go under
  `2.x`, not `1.x`. (Prismata and UCM are both injection-motivated but classified as defenses.)
- Pure benchmarks go under `3.x`, not scattered by topic into `1.x`.
- When unsure, **include it and state your reasoning** in the PR — let the maintainer decide
  rather than silently dropping it. But be decisive about rejecting pure capability work.

## Local validation

```bash
pip install pyyaml

python3 scripts/build.py              # generate READMEs + docs/
python3 scripts/build.py --check      # validate only, no writes
python3 scripts/check_links.py --sample 8   # spot-check arXiv metadata
```

`check_links.py` validates three things — CI fails on any of them:

1. arXiv ID is reachable (catches 404s and `XXXXX` placeholders)
2. **Returned title matches the YAML exactly** (catches wrong IDs and fabricated entries)
3. **v1 date matches the `date` field** (catches using a v2 revision month as the first-submission month)

Check 2 is not optional. An HTTP 200 does not catch an ID that points at a *different* real paper.
